Pull request #{{PR}} in {{REPO}} is open for your branch, and a reviewer twin (Codex, in the Orca terminal {{REVIEWER_ADDRESS}}) is reviewing it. From now on you run a loop with that reviewer, without waiting for the orchestrator:

1. The reviewer posts its findings as inline comments on the pull request and then messages you. On each message, list EVERY top-level thread (`gh api repos/{{REPO}}/pulls/{{PR}}/comments --paginate --jq '.[] | select(.in_reply_to_id == null) | "\(.id) \(.path):\(.line)\n\(.body)\n"'`), never only the new ones.
2. Decide each one on its merits: fix it, or reject it with the reason. A finding that would change an approved design or decision is not yours to settle: send it to the orchestrator (`orca orchestration send --to orca_session_id:{{ORCHESTRATOR_SESSION}} ...`) and leave that thread with a reply saying it is escalated.
3. Tests and CI are yours alone: the reviewer runs nothing and does not look at CI. Fix in small commits in the repository's style, run every gate your original brief named, then push to this pull request's branch. You are authorized to push to this branch for review fixes; never force-push, never push anywhere else, never merge or close.
4. Reply on every thread (`gh api -X POST repos/{{REPO}}/pulls/{{PR}}/comments/<id>/replies -f body=...`): what you changed and the commit, or why you did not change it, and the result of any run the finding asked for. No thread stays silent.
5. Hand back right after the push, without waiting for CI: `orca orchestration send --to {{REVIEWER_ADDRESS}} --subject "PR #{{PR}} round <n> addressed at <sha>" --body "<one line per thread: fixed in <sha>, rejected because ..., or escalated>"`. Then check CI on that head yourself (`gh pr checks {{PR}} -R {{REPO}}`) and fix what is red before your next handback. If no run starts, the pull request conflicts with its base: merge the base branch in.
6. Repeat until the reviewer says "review complete". Then see CI green on the final head and report to the orchestrator: the rounds, what was rejected and why, the final head, the gate and CI results.

If an `orca orchestration send` fails, write what you would have sent to `.scratch/review-handback.md` in your worktree and say so in chat.
